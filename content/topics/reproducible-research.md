## 概述 {#overview}

网络是构建出来的：节点怎么定义、边用什么统计量、阈值取多少、社团算法和随机基线怎么选，每一步都是分析者的选择。本专题讨论的核心问题是：**一个网络分析的结论，是数据的性质，还是分析选择的产物？**

围绕这个问题，本专题按一项研究的生命周期组织：

1. **设计阶段**：怎样把研究方向改写成可回答、可检验的网络研究问题（[提出网络研究问题](reproducible-research.research-questions.html)），怎样在看到结果之前写下分析计划（[预注册与分析计划](reproducible-research.preregistration.html)），以及需要多大的样本（[统计功效与样本量](reproducible-research.power-sample-size.html)）。
2. **执行阶段**：怎样组织数据与代码，使结果可以被他人和自己复算（[可复算的分析](reproducible-research.reproducible-analysis.html)、[计算环境与工作流](reproducible-research.computational-environment.html)、[随机性控制](reproducible-research.randomness-robustness.html)）。
3. **检验阶段**：怎样用敏感性分析、替代解释排查和多元宇宙分析检验结论的稳健性（[敏感性分析与替代解释](reproducible-research.sensitivity-analysis.html)、[多元宇宙分析与设定曲线](reproducible-research.multiverse-analysis.html)）。
4. **报告与共享阶段**：每一步应报告什么（[网络研究的报告清单](reproducible-research.reporting-checklist.html)），数据和代码怎样共享（[数据与代码共享](reproducible-research.open-data-code.html)），以及怎样负责任地使用和披露生成式 AI 辅助工具。

网络研究中关于可重复性的争论与案例见[可重复性危机与负结果](reproducible-research.replication-cases.html)。这些方法把其他专题中的具体问题收束为同一原则：[脑连接组：结构与功能连接](brain-connectome.html)中的阈值选择、[症状网络与网络精神病学](symptom-networks.html)中的稳定性检验、[基因调控网络推断与共表达分析](gene-network-inference.html)中的推断可靠性、[疾病模块、网络邻近度与药物重定位](network-medicine.html)中的度匹配零模型，都是它的不同侧面。网络构建中的统计检验与重抽样方法见[网络构建与统计验证](network-construction.html)，网络分析的一般流程与工具见[网络分析流程与 NetworkX 实践](analysis-workflow.html)，结果的图表呈现与报告结构见[结果呈现与研究前沿](reporting-frontiers.html)。

::: {.callout-def}
**几个容易混淆的术语**（本站采用 The Turing Way 手册的划分）：同一数据 + 同一分析 → 相同结果，称为**可复算**（reproducible）；不同数据 + 同一分析 → 一致结论，称为**可重复**（replicable）；同一数据 + 不同的合理分析 → 一致结论，称为**稳健**（robust）；不同数据 + 不同分析 → 一致结论，称为**可推广**（generalisable）。不同领域对 reproducible 与 replicable 的用法并不统一，写作时应先给出定义。
:::

## 提出网络研究问题 {#research-questions}

### 从研究方向到研究问题

“用 STRING 分析阿尔茨海默病”是方向，不是问题。一个可回答的研究问题至少要说清四件事：

| 要素 | 需要回答 | 例子 |
|---|---|---|
| 系统 | 研究对象是什么？ | 阿尔茨海默病相关基因在人类 PPI 网络中的位置 |
| 节点与边 | 节点代表什么？边代表什么？数据从哪来？ | 节点为蛋白；边为 STRING 中综合置信度 ≥ 0.7 的相互作用 |
| 问题类型 | 描述、比较、预测，还是机制？ | 比较：AD 基因是否比度匹配随机基因更聚集？ |
| 判断标准 | 什么结果支持/反对你的假设？ | LCC 的 $z > 2$ 且在置信度 0.4–0.9 范围内都成立 |

::: {.callout-def}
**“为什么需要网络”检验**：如果把网络去掉、只看单个基因（或单个脑区、单个症状）的统计量，就能回答你的问题，那么网络分析不是必要的。好的网络问题依赖于**元素之间的关系**：模块、路径、邻近、中心性、动力学。
:::

### 四类网络研究问题及其证据要求

不同类型的问题需要不同的证据，混淆问题类型是网络研究中最常见的过度解读来源之一。

| 问题类型 | 典型表述 | 需要的对照与检验 | 不能得出的结论 |
|---|---|---|---|
| 描述 | 这个网络是否有模块结构、重尾度分布？ | 合适的零模型（ER、度保持随机化）；拟合优度检验 | 结构的生物学成因 |
| 比较 | 病例组与对照组的网络是否不同？ | 密度匹配或加权指标；置换检验；混杂因素控制 | 差异是疾病的原因 |
| 预测 | 网络特征能否预测诊断、疗效、药物适应证？ | 独立测试集或嵌套交叉验证；外部验证 | 被选中的特征具有因果作用 |
| 机制 | 干预某个节点是否改变系统状态？ | 干预数据、纵向数据或明确的动力学模型 | 仅凭横断面相关推出因果方向 |

在开始分析前，最好把问题写成一个**估计目标**（estimand）：在什么人群、用什么测量、比较什么、用哪个数值概括。例如“在 18–65 岁抑郁门诊患者中，PHQ-9 各症状在正则化偏相关网络中的强度中心性，其排序在病例删除 bootstrap 下的 CS 系数是否 ≥ 0.5”。估计目标一旦确定，阈值、算法等分析选择就成为“对同一个目标的不同估计方式”，便于后续做敏感性分析。

### 假设、探索与“结果已知后提出假设”

网络分析常常是探索性的，这本身没有问题；问题在于把探索性结果写成验证性结论。Kerr（1998）把“在看到结果之后提出假设，并把它当作事先假设来报告”称为 **HARKing**。网络研究中常见的形式是：先计算几十个节点的中心性，再把排第一的节点说成“预期的核心节点”。避免的办法是在研究记录（最好是预注册）中区分**验证性问题**（事先写明假设和检验）与**探索性问题**（报告为产生假设，需要在新数据中验证）。

### 检查清单：研究问题

- [ ] 问题能用一句话说清，并且包含“与什么比较”。
- [ ] 节点和边的定义在生物学上有明确含义，而且你能说清它们**不能**代表什么（例如相关边不代表调控）。
- [ ] 有合适的零模型或对照组（见[网络结构指标与随机图](network-metrics.html)、[社团结构与社区发现](community-structure.html)、[疾病模块、网络邻近度与药物重定位](network-medicine.html)）。
- [ ] 数据可以在研究周期内获取（注意 DrugBank、DisGeNET、HCP 等需要注册或协议，见[常见生物医学网络数据与分析方向](analysis-workflow.biomedical-datasets.html)）。
- [ ] 样本量足以估计你关心的量（见[统计功效与样本量](reproducible-research.power-sample-size.html)）。
- [ ] 计算量在你的硬件上可行（先用小规模子集试跑）。
- [ ] 区分了验证性问题与探索性问题。
- [ ] 至少预先想好一个“如果结果是阴性，我能学到什么”。

::: {.callout-bio}
**问题改写示例**：“构建抑郁症状网络，找出核心症状。”→“在 NHANES 的 PHQ-9 数据中，哪些症状的强度中心性在 bootstrap 重采样下稳定排在前列？排序是否在性别分组中一致？”后者明确了数据、指标、稳定性标准和比较对象。
:::

## 预注册与分析计划 {#preregistration}

### 为什么要在看到结果之前写下计划

Nosek 等（2018）把科学推理区分为**预测**（用新观测检验事先的假设）和**事后解释**（postdiction，用已有观测产生假设）。两者都有价值，但人的后见之明偏差使研究者很难在事后分清自己做的是哪一种。**预注册**（preregistration）就是在观察研究结果之前，把研究问题和分析计划以带时间戳、不可修改的形式存档（例如 OSF Registries、AsPredicted，临床试验则在 ClinicalTrials.gov 等平台登记）。

**注册报告**（Registered Report）更进一步：期刊在数据收集或分析之前，先对引言和方法进行同行评审；通过“原则性接收”后，只要按计划执行，无论结果阳性或阴性都予以发表（Chambers & Tzavella 2022）。这直接针对发表偏倚。

::: {.callout-def}
**预注册**：在观察研究结果之前，把假设、数据来源、纳入排除标准、变量定义、主分析方法、推断标准和计划中的敏感性分析写成带时间戳的公开（或暂时封存）文档。预注册不禁止探索性分析，它的作用是让读者区分哪些分析是事先计划的、哪些是事后进行的。
:::

### 网络研究的分析计划应写什么

网络分析的“分岔点”比一般统计分析更多，分析计划应逐项写明：

| 环节 | 计划中要写明的内容 |
|---|---|
| 数据 | 数据库或队列名称与版本、下载日期；纳入排除标准；预期样本量及其依据 |
| 节点 | 节点定义（脑图谱及版本、基因 ID 体系与映射规则、症状条目）；合并或剔除节点的规则 |
| 边 | 统计量（Pearson/Spearman/偏相关/互信息/数据库置信度）；正则化方法与调参准则 |
| 稀疏化 | 阈值类型与取值（或扫描范围）；是否保留负边与权重 |
| 指标 | 主要指标（不超过少数几个）及其计算软件；次要指标单独列出 |
| 推断 | 零模型类型与随机网络数 $B$；检验的单侧/双侧；多重比较校正方法；显著性阈值 |
| 稳健性 | 计划中的敏感性分析或多元宇宙维度；稳定性检验（bootstrap 类型与次数） |
| 偏离 | 如果数据不满足假设（如偏态、缺失），采用什么备选方案 |

### 对已有数据的预注册

网络研究大量使用公共数据（UK Biobank、HCP、TCGA、STRING 等），研究者在设计时往往已经接触过数据。Nosek 等（2018）讨论了这类“不理想情形”下的策略；Van den Akker 等（2021）专门给出了二次数据分析的预注册模板，要求说明作者此前对数据了解多少、看过哪些变量。可行的做法包括：

- **分割数据**：把数据随机分成探索集和确认集，只在探索集上调整流程，然后把最终流程预注册，再在确认集上运行一次。
- **盲化**：在确定流程前打乱组标签或结局变量，只用不含结局的数据检查质量与分布。
- **如实声明**：说明预注册时已获得数据但未进行相关分析，并列出已知的信息。

::: {.callout-warn}
预注册之后偏离计划是常见且正当的（例如发现变量严重偏态而换用 Spearman 相关），关键是**透明**：在论文中列出每一处偏离、原因，以及按原计划分析得到的结果。把偏离藏起来，比不做预注册更有害。
:::

## 可复算的分析 {#reproducible-analysis}

### 两个概念

::: {.callout-def}
**可复算（reproducible）**：用相同的数据、相同的代码和步骤，得到相同的结果。**可重复（replicable）**：用新的数据、按相同的方法，得到一致的结论。任何计算分析至少要做到可复算；有条件时，用第二个数据集或子样本检验可重复性。
:::

可复算看似是最低要求，实际上并不容易达到。Stodden 等（2018）随机抽取 *Science* 在 2011 年实行数据与代码政策后发表的 204 篇计算类论文，向作者索取材料：只拿到了其中 44% 的数据和代码，能复现结果的为 26%。Trisovic 等（2022）在干净环境中重新运行 Harvard Dataverse 上 2000 多个复现数据包中的 9000 多个 R 脚本，74% 的文件初次运行即报错，经自动清理代码后仍有 56% 报错。这些数字说明：“代码已共享”不等于“结果可复算”。

### Sandve 等的十条规则

Sandve 等（2013）的十条规则至今仍是计算可复算性的基本框架。下面按其要点给出网络分析中的对应做法：

| 规则要点 | 网络分析中的做法 |
|---|---|
| 1. 记录每个结果是怎样产生的 | 每张图、每个数值都能追溯到一个脚本和一组参数 |
| 2. 避免手工处理数据 | 不在 Excel 里手改基因名；ID 映射写成代码并保存映射表 |
| 3. 存档所用外部程序的确切版本 | 记录 networkx、igraph、bctpy、bootnet 等的版本；数据库同样要记版本 |
| 4. 对自己的脚本做版本控制 | 用 Git，每个结果对应一个提交号 |
| 5. 尽量用标准格式保存中间结果 | 保存邻接矩阵、边列表（如 `.npz`、`.csv`、GraphML），而不只保存最终图 |
| 6. 有随机性的分析要记录随机种子 | Louvain、bootstrap、度保持随机化都要记录种子（见[随机性控制](reproducible-research.randomness-robustness.html)） |
| 7. 保存图背后的原始数值 | 每张敏感性曲线都保存对应的数值表 |
| 8. 输出分层次的结果 | 汇总表 → 每个参数组合的结果 → 单次运行的日志 |
| 9. 把文中陈述与具体结果对应起来 | 正文中的每个数值都能在结果文件中找到 |
| 10. 公开脚本、运行记录和结果 | 见[数据与代码共享](reproducible-research.open-data-code.html) |

### 七条日常做法

1. **原始数据只读**：下载的原始文件不手工修改，所有清洗步骤写在代码里。
2. **记录数据版本**：数据库名称、版本号和下载日期写进 README，例如“STRING v12.0，2026-11-10 下载，人类 9606，综合置信度 ≥ 700”。数据库会更新，不记版本就无法复算。
3. **用脚本，不用鼠标**：Cytoscape、Gephi 适合可视化和探索，但关键数值结果应由脚本生成。确需手工操作时，逐步写进实验记录。
4. **固定随机种子**：Louvain、随机网络、bootstrap、置换检验都有随机性。固定种子是为了**可复算**；报告结论时则要跑多个种子，说明结论不依赖于某一个种子（见[敏感性分析与替代解释](reproducible-research.sensitivity-analysis.html)）。
5. **记录环境**：`requirements.txt` 或 `environment.yml` 写明 Python/R 和关键包版本（例如 networkx 3.x 的 Louvain 实现与旧版不同），详见[计算环境与工作流](reproducible-research.computational-environment.html)。
6. **版本控制**：用 Git 管理代码和文档，每完成一步就提交一次，提交说明写清“做了什么”。
7. **一键重跑**：最终发布前，从原始数据出发运行一遍完整流程，确认所有图表都能重新生成。

推荐的项目目录（与 The Turing Way 所说的“研究纲要”（research compendium）思路一致）：

```text
project/
├── README.md          # 问题、数据来源与版本、运行方法
├── LICENSE            # 代码许可；数据另行说明
├── environment.yml    # 或 requirements.txt + 锁定文件
├── data/raw/          # 原始数据（只读，不提交大文件，写明下载方式）
├── data/processed/    # 由代码生成
├── code/              # 01_clean.py, 02_build_network.py, 03_analysis.py ...
├── results/           # 图表与数值结果，由代码生成
└── report/            # 报告与幻灯片
```

### 溯源记录

**溯源**（provenance）指每个结果从哪些输入、经过哪些步骤、在什么环境下得到。最轻量的做法是每次运行时自动写一个“运行清单”：软件版本、参数、随机种子，以及输入与输出文件的 SHA-256 哈希。哈希相同说明文件逐字节相同；换机器后输出哈希改变，就可以按清单逐项排查是数据、参数还是软件版本变了（见本专题代码示例“运行清单”）。

## 计算环境与工作流 {#computational-environment}

同一段代码在不同的软件版本下可能给出不同的结果：默认参数会变，算法实现会改，随机数生成器也可能改变。Burger 等（2023）在心理网络报告规范中专门指出，软件包的估计默认值会随版本更新而改变，因此即使使用默认参数也要报告参数和版本。

### 四个层次

| 层次 | 工具举例 | 解决的问题 | 局限 |
|---|---|---|---|
| 记录版本 | `pip freeze`、`sessionInfo()`、运行清单 | 知道用的是什么版本 | 不保证能重新装出来 |
| 锁定依赖 | `requirements.txt`（精确版本）、conda `environment.yml` 与锁定文件、R 的 `renv.lock` | 可以重建相同的包集合 | 依赖操作系统和底层库 |
| 容器 | Docker、Apptainer/Singularity（高性能计算集群常用） | 连同操作系统和系统库一起打包 | 镜像体积大；硬件差异仍可能带来浮点差异 |
| 工作流管理 | Make、Snakemake、Nextflow | 记录步骤之间的依赖关系，只重跑受影响的步骤 | 需要学习成本 |

Boettiger（2015）介绍了用 Docker 打包研究计算环境的做法；Grüning 等（2018）针对生命科学提出了组合使用包管理器（如 Bioconda）、容器和工作流系统的分层方案。对于大多数网络分析项目，“精确锁定版本的环境文件 + Git + 一个能从原始数据跑到最终图表的主脚本（或 Makefile）”已经足够；需要在集群或跨机构复算时，再加上容器。

### 让代码可以被检验

- **小型测试**：对关键函数写断言，例如“三角形图的平均聚集系数等于 1”“度保持随机化后度序列不变”。
- **持续集成**（continuous integration, CI）：在代码托管平台上每次提交时自动在干净环境中运行测试，相当于定期做一次“别人能不能跑起来”的检查。
- **代码审阅**：请合作者在自己的机器上按 README 运行一遍。

The Turing Way 手册的“可复现研究指南”系统覆盖了版本控制、许可、研究数据管理、可复现环境、代码文档与测试、代码审阅、持续集成、用 Make 组织流程和研究纲要等主题，可作为实践手册查阅。

::: {.callout-warn}
**浮点结果的“可复算”应以容差为准**。不同的 CPU、BLAS 库或并行线程数可能导致矩阵求逆、特征分解结果在末位不同；对接近阈值的边，这种差异甚至会改变边是否存在。复算时应比较数值是否在合理容差内一致，并检查结论（而不是逐字节输出）是否改变。
:::

## 数据与代码共享 {#open-data-code}

### FAIR 原则

Wilkinson 等（2016）提出的 FAIR 原则要求科研数据（及其元数据）**可发现**（Findable）、**可访问**（Accessible）、**可互操作**（Interoperable）、**可重用**（Reusable）。这些原则面向人和机器两类使用者，强调的是元数据和标识符，而不是“必须完全公开”。

| 原则 | 要点 | 网络研究中的做法 |
|---|---|---|
| 可发现 | 数据有全局唯一、持久的标识符（如 DOI）；有丰富的元数据并被索引 | 把处理后的网络（边列表、邻接矩阵）存入 Zenodo、Figshare、OSF 等可分配 DOI 的存储库 |
| 可访问 | 通过标准协议按标识符获取；即使数据不可再获取，元数据仍保留 | 受控数据写明申请途径；元数据和代码公开 |
| 可互操作 | 使用通用的格式、词表和本体 | 基因用 Entrez/Ensembl/UniProt ID 并注明版本；脑区用标准图谱名称；影像数据采用 BIDS 结构（Gorgolewski 等 2016） |
| 可重用 | 有清楚的许可、详细的来源说明、符合领域标准 | 写明数据许可、处理步骤、节点与边的定义和单位 |

### 许可

没有许可声明的代码，在多数法律体系下他人并不能合法地复用。Morin 等（2012）为科研程序员总结了软件许可的基本知识。常见的选择：

- **代码**：MIT、BSD（宽松，允许闭源再利用）；GPL（要求衍生作品以相同许可开源）。
- **数据与文本**：CC BY 4.0（要求署名）；CC0（放弃权利，便于整合进数据库）。
- **上游数据的约束**：网络数据常常由多个数据库派生，派生数据的共享受上游许可约束。例如部分数据库仅限非商业使用或需要注册，再分发前要核对其条款；做不到再分发时，共享**生成数据的代码**和**下载说明**。

软件本身也应被引用：Smith 等（2016）提出的软件引用原则建议在参考文献中引用所用软件（尽量引用带版本的存档 DOI）。

### 数据可用性声明与敏感数据

多数期刊要求“数据可用性声明”（data availability statement）和代码可用性声明。一个好的声明应说明：数据存放在哪里（链接或 DOI）、在什么条件下可获取、哪些数据因隐私或协议不能公开以及申请途径。“数据可向通讯作者合理索取”这种写法的实际可获得性很低（参见上文 Stodden 等 2018 的结果），应尽量避免。

::: {.callout-warn}
**患者数据的网络并非“去标识化”就安全**。个体水平的连接组、个体症状时间序列或罕见基因型组合都可能被再识别。共享这类数据要遵守伦理审批和数据使用协议；常见的折中方案是共享组水平的相关矩阵或网络、合成数据，或通过受控访问平台共享。
:::

::: {.callout-bio}
**共享相关矩阵即可复算的例子**：Fried 等（2018）在四个创伤后应激障碍临床样本的网络研究中，公开了代码、模型输出和各样本的相关矩阵，使正则化偏相关网络可以在不接触个体数据的情况下被完全复算。对基于高斯图模型的症状网络，相关矩阵加样本量就是充分的输入；这一做法值得在涉及隐私的研究中借鉴。
:::

## 随机性控制 {#randomness-robustness}

网络分析中的随机性来源很多：Louvain/Leiden 等启发式算法的节点访问顺序、随机网络与度保持随机化、bootstrap 与置换检验、交叉验证的分割、随机梯度训练的图神经网络。随机性需要分两层处理。

### 第一层：可复算——记录并固定种子

- 在 Python 中用 `numpy.random.default_rng(seed)` 创建独立的生成器并显式传递，而不是依赖全局状态；NetworkX 中有随机性的函数大多接受 `seed` 参数。
- 并行计算时，为每个进程派生独立的子种子（如 NumPy 的 `SeedSequence.spawn`），并记录主种子。Burger 等（2023）提醒：使用并行计算时，单纯设定一个种子并不一定能固定结果。
- 种子应在分析开始前确定（例如写进分析计划），而不是事后挑选。

### 第二层：稳健——结论不应依赖某一个种子

固定种子只保证别人能得到**同一个**随机结果，不能说明这个结果有代表性。对有随机性的算法，应报告多个种子下结果的分布：社团数、模块度 $Q$ 的范围，划分之间的一致性（如调整兰德指数），或基于多次运行的共识划分（见[社团结构与社区发现](community-structure.html)）。

### 蒙特卡洛误差

用 $B$ 个随机网络或 $B$ 次置换估计的 $z$ 分数和 $p$ 值本身是带误差的估计量。

::: {.callout-def}
**经验 $p$ 值与蒙特卡洛标准误**：若 $B$ 次置换中有 $b$ 次统计量不小于观测值，推荐的经验 $p$ 值为
$$\hat p = \frac{b+1}{B+1},$$
它保证在原假设下检验不会过于宽松，且永远不为 0（Phipson & Smyth 2010）。$\hat p$ 的蒙特卡洛标准误近似为 $\sqrt{p(1-p)/B}$。
:::

**算例**：若真实 $p \approx 0.04$，$B = 100$ 时标准误约 $\sqrt{0.04 \times 0.96/100} \approx 0.020$，与 0.05 的差距只有半个标准误，换一个种子就可能越过阈值；$B = 1000$ 时标准误约 0.006。另一个常被忽视的事实是 $\hat p$ 的最小可达值为 $1/(B+1)$：用 19 个随机网络做检验，$p$ 永远不可能小于 0.05；若还要做 100 次多重比较的 Bonferroni 校正，每个检验至少需要约 2000 次置换才有可能达到阈值。

::: {.callout-warn}
“换种子直到显著”和“增加或减少置换次数直到显著”都是研究者自由度。随机网络数 $B$ 和种子应事先确定并报告；如果结论在不同种子之间翻转，说明 $B$ 不够大，或者效应本身处在边界上。
:::

## 敏感性分析与替代解释 {#sensitivity-analysis}

### 分析选择的“分岔花园”

一个网络分析要经过许多选择：节点怎么定义、边用什么统计量、阈值取多少、社团算法用哪个、随机基线怎么构造……每个选择都“合理”，但组合起来，结论可能截然不同。Botvinik-Nezer 等（2020）请 70 个团队独立分析同一份 fMRI 数据、检验同样 9 个事先确定的假设：没有两个团队选择了完全相同的分析流程，各团队对同一假设给出的“显著/不显著”结论差异相当大，即使在中间统计图高度相关的团队之间也是如此。

::: {.callout-def}
**敏感性分析（sensitivity analysis）**：系统改变关键分析选择，观察主要结论是否保持。若在合理范围内结论都成立，结论是**稳健的**；若只在某个选择下成立，必须如实报告。把所有合理选择组合起来逐一运行、汇总结果的做法称为**多元宇宙分析（multiverse analysis）**，见[多元宇宙分析与设定曲线](reproducible-research.multiverse-analysis.html)。
:::

### 网络分析中常见的敏感点

| 分析环节 | 常见选择 | 敏感性做法 | 相关专题 |
|---|---|---|---|
| 节点定义 | 不同脑图谱与分辨率；基因 ID 映射规则；症状条目合并与否 | 至少比较两种节点定义 | [脑连接组](brain-connectome.html)、[网络构建](network-construction.html) |
| 边的定义 | 相关、偏相关、互信息 | 至少比较两种 | [脑连接组](brain-connectome.html)、[症状网络](symptom-networks.html)、[基因网络推断](gene-network-inference.html) |
| 阈值/密度 | 绝对阈值、比例阈值、加权 | 扫描一段密度区间并画曲线 | [脑连接组](brain-connectome.html) |
| 数据库置信度 | STRING 0.4 / 0.7 / 0.9 | 报告三档下的结果 | [生物分子网络](molecular-networks.html)、[网络医学](network-medicine.html) |
| 预处理 | 是否全局信号回归、头动处理策略、批次校正 | 主要预处理选择各跑一次 | [脑连接组](brain-connectome.html) |
| 社团检测 | Louvain 种子、分辨率参数 | 多种子、共识划分、报告 Q 的范围 | [社团结构与社区发现](community-structure.html) |
| 零模型 | ER、度保持重连、度匹配抽样 | 说明选择理由，必要时比较两种 | [网络结构指标与随机图](network-metrics.html)、[网络医学](network-medicine.html) |
| 样本 | 全部样本、去除离群、子样本 | bootstrap 或留一法 | [症状网络](symptom-networks.html)、[网络构建与统计验证](network-construction.stability-reproducibility.html) |

### 替代解释排查表

看到一个“有趣”的结果时，先问下面五个问题：

1. **密度/规模差异**：两组网络的边数不同，是否就足以解释指标差异？（见本专题代码示例“替代解释”）
2. **度与研究偏倚**：结果是否只是“热门基因/节点连边多”的反映？是否做了度匹配？
3. **混杂因素**：头动、批次、细胞组成、年龄、用药是否可能同时影响网络和结果？
4. **多重比较**：检验了多少个节点、多少个指标？是否做了 FDR 校正？
5. **循环论证（double dipping）**：是否用同一份数据既选择特征又检验特征？例如先挑出差异最大的边再比较它们的组间差异。

::: {.callout-def}
**循环分析（circular analysis, double dipping）**：用同一份数据既做选择（选边、选脑区、选基因、选参数），又对选择结果做统计检验或估计效应量。Kriegeskorte 等（2009）系统说明了它在系统神经科学中的危害：被选中的特征在同一数据中的效应被系统性高估，在纯噪声中也能得到“显著”结果。解决办法是选择与检验使用独立数据（分半、留出集、交叉验证），或者把选择步骤整体放进置换检验的每一次循环中。
:::

本专题的代码示例“循环论证”在不存在任何组间差异的模拟数据上演示：先在全部数据中挑出差异最大的 10 条边再检验，几乎每次都“显著”；改为一半数据选边、另一半检验后，“显著”比例回到名义水平 5% 左右。

::: {.callout-warn}
敏感性分析不是“找一个让结果显著的设置”。正确顺序是：**先**在研究计划中写明主分析的选择和要检查的敏感点，**再**运行并如实报告所有结果。反过来做，就成了 Simmons 等（2011）所说的“研究者自由度”导致的假阳性。Wicherts 等（2016）把研究设计、执行、分析和报告各阶段的研究者自由度整理成检查清单，可在写分析计划时对照。
:::

## 多元宇宙分析与设定曲线 {#multiverse-analysis}

### 从“一个分析”到“分析的集合”

Steegen 等（2016）指出，原始数据在变成分析数据集之前要经过一系列处理选择，每种合理选择组合都产生一个“数据宇宙”；只报告其中一个，等于隐藏了结论对处理选择的依赖。**多元宇宙分析**就是把所有合理的选择组合都跑一遍，并报告结果在这些宇宙中的分布。

Simonsohn 等（2020）提出的**设定曲线分析**（specification curve analysis）给出了一个标准化的流程：

1. **界定设定**：列出在理论上同样合理、统计上有效、彼此不冗余的分析设定。
2. **呈现结果**：把所有设定的效应量从小到大排序作图（设定曲线），下方用指示面板标出每个设定对应的选择。
3. **联合推断**：在原假设下（如打乱组标签）重复整个过程，构造“全部设定的结果都只是噪声”时设定曲线的分布，据此检验观测到的曲线是否异常（例如中位效应量、显著设定的个数）。

::: {.callout-def}
**多元宇宙的规模**：若有 $K$ 个分析环节，第 $k$ 个环节有 $m_k$ 种合理选择，则宇宙总数为 $\prod_{k=1}^{K} m_k$。例如 3 种边统计量 × 4 个密度 × 2 个指标 = 24 个宇宙；再加 3 种图谱和 2 种预处理就变成 144 个。
:::

### 网络构建中的具体做法

- **列维度**：对照“网络分析中常见的敏感点”表，选出与研究问题相关、且确实没有公认最优选择的环节。已知错误的选择（如对计数数据用未经变换的 Pearson 相关）不应放进来。
- **控制规模**：组合爆炸时，可以只对少数关键维度做全组合，其余维度单独变动；或像 Dafflon 等（2022）那样，在由流水线相似性构成的低维空间中用主动学习近似地探索整个多元宇宙。
- **推断层次**：对每个宇宙都做零模型或置换检验，且置换要包住**整条流水线**（每次置换都重新计算相关、阈值化和指标）。
- **呈现**：设定曲线、按维度分组的效应量箱线图，或“每个维度对结果方差的贡献”。报告显著宇宙的比例时，同时报告效应方向是否一致。
- **区分“多元宇宙”与“流水线评估”**：Luppi 等（2024）系统评估了 768 条静息态 fMRI 网络构建流水线（组合脑图谱、连接定义与全局信号回归等选择），用头动混杂、重测一致性、对个体差异和实验效应的敏感性等标准评价它们，发现多数流水线至少在一项标准上不合格，但也存在一组在多个数据集上都表现良好的流水线。这提示：并非所有宇宙都同样可信，如果已有独立的质量标准，应先用它排除不合格的选择，再对剩下的选择做多元宇宙分析。

::: {.callout-bio}
**多团队分析：多元宇宙的“自然实验”**。除 Botvinik-Nezer 等（2020）的 fMRI 研究外，Silberzahn 等（2018）请 29 个团队（61 名分析者）用同一数据回答同一问题，估计的效应量（比值比）从 0.89 到 2.93 不等，20 个团队（69%）得到显著正效应、9 个不显著；分析者的先验信念和专业水平都不能解释这种差异。在基因网络推断中，DREAM5 对多种方法的社区评测也显示，不同方法推断出的网络差异很大，而整合多种方法的结果更稳健（见 [Marbach 2012](paper-marbach2012_wisdom.html)）。
:::

本专题代码示例“多元宇宙分析”构造了 24 个宇宙，在每个宇宙中做 200 次组标签置换，按效应量排序打印设定曲线。在这组模拟数据中，效应的方向和显著性都随边统计量、密度和指标而变化，只有少数宇宙达到显著。这种结果本身就是有价值的报告内容。

::: {.callout-warn}
多元宇宙分析不能把有缺陷的选择“平均”成可信结论，也不是“显著宇宙超过一半就算成立”。它回答的是“结论对哪些选择敏感”。理想情况下，主分析在预注册中指定，多元宇宙作为稳健性检验同样事先规划。
:::

## 统计功效与样本量 {#power-sample-size}

### 低功效的双重代价

Button 等（2013）指出，神经科学研究的平均统计功效很低，后果不只是漏检真实效应：在功效低的研究中，显著结果为真阳性的概率也更低，而且被报告的显著效应量会被系统性高估（“赢家诅咒”）。Marek 等（2022）用总计约 5 万人的三个大型影像数据集说明，大脑–表型的全脑关联效应比以往认为的小得多，在典型样本量下（影像研究的中位样本量约为 25 人）会出现功效不足、效应量虚高和复现失败；样本量增加到数千人后，复现率才明显改善。

网络分析对样本量的需求通常比单变量分析更高：一个 $p$ 节点网络有 $p(p-1)/2$ 个边参数，偏相关还要同时控制其他 $p-2$ 个变量。

### 单条边的样本量近似

对相关系数 $r$，Fisher z 变换 $z = \operatorname{artanh}(r)$ 近似服从正态分布，标准误为 $1/\sqrt{n-3}$；对控制了 $k$ 个变量的偏相关，标准误近似为 $1/\sqrt{n-3-k}$。由此，在双侧显著性水平 $\alpha$ 下以功效 $1-\beta$ 检出总体值为 $\rho$ 的边，所需样本量近似为

$$
n \approx \left(\frac{z_{1-\alpha/2} + z_{1-\beta}}{\operatorname{artanh}(\rho)}\right)^2 + 3 + k .
$$

**算例**：$\rho = 0.2$，$\alpha = 0.05$，功效 0.8，$k = 0$：$\operatorname{artanh}(0.2) \approx 0.2027$，$(1.960 + 0.842)^2 \approx 7.85$，$7.85 / 0.2027^2 \approx 191$，故 $n \approx 194$。若网络有 15 个节点（105 条边），对所有边做 Bonferroni 校正（$\alpha = 0.05/105$）且偏相关控制 13 个变量，所需样本量约为 474（见本专题代码示例“统计功效”）。

### 基于模拟的样本量规划

上面的公式只针对单条边的显著性检验。实际的网络估计常用正则化方法（如 EBICglasso），关心的量也不止单条边（还有灵敏度、特异度、中心性排序的稳定性），此时更可靠的是**模拟**：假设一个合理的真实网络，在不同样本量下反复生成数据并按计划的流程估计，统计关心的性能指标。Constantin 等（2026，*Psychological Methods*）把这一过程做成通用的蒙特卡洛算法（R 包 powerly），需要三个输入：假设的网络结构、性能指标及目标值（如灵敏度 0.6）、以及达到目标的概率要求（如 0.8）。Isvoranu 与 Epskamp（2023）对多种高斯图模型估计方法做了大规模模拟比较，结论是“发现”（灵敏度）与“谨慎”（特异度、精确度）之间总存在取舍，应根据研究问题选择估计方法。

::: {.callout-bio}
**脑网络与症状网络的样本量**：在 Marek 等（2022）的结果之后，个体差异类脑网络研究越来越依赖 UK Biobank、ABCD 等大型队列；而组水平的网络拓扑描述（如模块结构）通常比个体差异关联需要的样本少。症状网络中，Epskamp 等（2018）建议的病例删除 bootstrap 和 CS 系数（见[网络构建与统计验证](network-construction.stability-reproducibility.html)）可在事后检查样本是否足以支持中心性排序；事前规划则应使用模拟。
:::

::: {.callout-warn}
**事后功效分析没有意义**。用观测到的效应量计算“观测功效”，只是 $p$ 值的另一种表达。样本量规划应在收集或分析数据之前，基于文献、先导数据或最小有意义效应来做。检验不显著时，应报告效应量的置信区间，说明数据能排除多大的效应。
:::

## 网络研究的报告清单 {#reporting-checklist}

报告规范的作用是让读者能评价、复算和综合研究。通用规范（如观察性研究的 STROBE、临床试验的 CONSORT）不覆盖网络构建的细节，因此各领域出现了针对网络或影像的规范：Nichols 等（2017）的 COBIDAS 报告给出了 MRI 数据分析与共享的最佳实践和报告清单；Burger 等（2023）提出了横断面心理网络分析的报告标准，按方法和结果两部分组织，分为“通用分析流程”（每项研究都应报告）和“特定分析流程”（只在相关时报告），并用“需要注意的问题”专栏讨论解释上的陷阱。

Hallquist 与 Hillary（2019）回顾了 106 项临床静息态功能连接图论研究，发现节点划分和边定义差异极大、常见的“使各组边数相等”的做法在临床人群中可能制造虚假组间差异、各研究共同报告的图论指标很少以致难以做元分析。完整、统一的报告是解决这些问题的前提。

### 网络构建每一步应报告什么

下表综合了上述规范，可作为“迷你报告清单”使用（图表呈现与报告结构见[结果呈现与研究前沿](reporting-frontiers.report-structure.html)）：

| 步骤 | 必须报告 | 说明 |
|---|---|---|
| 样本 | 招募方式与人群；收集到与进入分析的样本数；是否按网络内变量筛选子样本 | 按总分阈值筛选病例会在子样本中诱导负边（Burger 等 2023 讨论的选择效应） |
| 数据来源 | 数据库名称、版本、下载日期；物种与 ID 体系 | 例如 STRING v12.0 人类，综合置信度阈值 |
| 变量与节点 | 测量工具及版本；节点定义（图谱名称与分辨率、基因映射规则）；合并、剔除节点的规则 | 同一构念的多个条目会产生拓扑重叠 |
| 预处理 | 变换、缺失数据处理（删除或插补方式）、离群值、批次与头动处理 | 问卷跳题结构不应简单用 0 插补 |
| 边的估计 | 统计量；估计方法与全部参数（包括默认值）；正则化调参准则 | 默认值会随软件版本改变 |
| 稀疏化 | 阈值类型与取值；是否保留负边和权重；密度 | 报告每组的实际密度 |
| 指标与算法 | 指标定义（加权/不加权）；算法与参数（如社团检测的分辨率） | 指标名称相同但定义可能不同 |
| 零模型与推断 | 零模型类型；随机网络或置换次数；检验方向；多重比较校正 | 报告 $B$ 和种子 |
| 准确性与稳定性 | bootstrap 类型与次数；边权区间；中心性的病例删除稳定性 | 中心性差异不稳定时不解释排序 |
| 敏感性分析 | 改变了哪些选择；每个选择下的结果 | 包括不支持假设的结果 |
| 软件与环境 | 软件、包及版本；随机种子；代码与数据可获取的位置 | 并行计算时说明种子如何派生 |
| 偏离与探索 | 与预注册的偏离；哪些分析是探索性的 | |

::: {.callout-warn}
报告清单不是解释指南：把所有项都报告了，并不意味着结论成立。例如，Burger 等（2023）提醒，中心性是在特定估计网络中计算出来的，不是变量本身的属性；同一个症状在一个网络中处于边缘，在加入其他变量的网络中可能变得居中。
:::

## 可重复性危机与负结果 {#replication-cases}

### 背景

开放科学合作组织（Open Science Collaboration, 2015）对三本心理学期刊上的 100 项研究做了高功效重复：原研究中 97% 报告了显著结果，而重复研究中只有 36% 显著，重复效应量平均约为原效应量的一半。Ioannidis（2005）则从先验概率、功效和偏倚出发论证，在许多研究条件下已发表的阳性结果为假的比例可能很高。网络研究同样经历了这些问题，以下是有文献支持的几个案例。

### 案例一：症状网络的可重复性争论

Forbes 等（2017）在两个相似的大型流行病学样本（美国 NCS-R，$n = 9282$；澳大利亚 NSMHWB，$n = 8841$）中比较抑郁和广泛性焦虑症状网络：关联网络稳定，但三种条件独立网络在方法和样本之间复现较差。在全样本的 6 个条件独立网络中，44% 的症状至少在一个中心性指标上被估计为“最有影响”，只有 13%–21% 的边在这些网络中被一致估计。Borsboom 等（2017）对同一数据重新分析，认为原结论很大程度上来自方法选择，网络实际上复现得较好；Burger 等（2023）在讨论问卷跳题结构时也引用了这场争论，说明对跳过的条目插补 0 会在数据中引入人为的依赖关系。

此后，Fried 等（2018）在四个跨文化、多中心的创伤后应激障碍临床治疗样本（合计 $N = 2782$，16 个症状）中估计正则化偏相关网络，网络结构的相关为 0.62–0.74，中心性估计的相关为 0.63–0.75：存在相当程度的共性，但并不完全一致。这场争论的主要收获是：整体结构比单条边和中心性排序更容易复现；网络结论需要稳定性检验、多样本比较和明确的报告（症状网络部分见[症状网络与网络精神病学](symptom-networks.network-comparison.html)）。

### 案例二：脑网络与脑–行为关联

- **分析灵活性**：Botvinik-Nezer 等（2020）的 70 团队研究（见上文）；预测市场显示，领域内研究者——即使直接了解该数据——也高估了得到显著结果的可能性。
- **网络构建流水线**：Luppi 等（2024）对 768 条功能连接组流水线的评估显示，不合适的流水线会产生系统性的误导结果。
- **样本量**：Marek 等（2022）说明了在典型样本量下的全脑关联研究普遍存在功效不足和效应量虚高。
- **方法异质性**：Hallquist 与 Hillary（2019）对 106 项临床图论研究的回顾（见[网络研究的报告清单](reproducible-research.reporting-checklist.html)）。

动态功能连接中的可重复性问题见[疾病中的脑网络与可重复性](dynamic-brain-networks.disease-reproducibility.html)。

### 案例三：网络科学的“普遍规律”再检验

Broido 与 Clauset（2019）用统一的统计方法检验了来自多个领域的近千个真实网络的度分布，发现具有强幂律证据的网络并不多见，多数网络与幂律相比，对数正态等其他重尾分布拟合得同样好或更好（见 [Broido 2019](paper-broido2019_rare.html) 与[小世界与无标度的统计判别](network-models.identification.html)）。这是一个“用更严格的方法重新检验广为接受的结论”的负结果，引发了关于“无标度”应如何定义的讨论。它说明，即使是网络科学的基础性结论，也需要明确的统计检验和数据集层面的复现。

### 负结果的价值与发表

负结果（阴性结果、未能复现）是知识的一部分。如果只有阳性结果被发表，文献中的效应量就会被系统性高估，元分析也会因此偏倚。可以采取的做法包括：

- 用**注册报告**的形式开展研究，使发表与结果无关（Chambers & Tzavella 2022）；
- 报告阴性结果时给出效应量的置信区间和功效（或可检出的最小效应），区分“证据表明不存在效应”与“证据不足”；
- 把未能复现的结果与原研究在数据、方法上的差异一并报告，使之成为可解释的信息；
- 把数据和代码共享到存储库，即使论文未发表，也可被元分析和后续研究使用。

## 负责任地使用 AI 辅助 {#ai-assistance}

生成式 AI 可以显著提高写代码和查资料的效率，也带来新的错误类型。一个可行的原则是：**可以使用，必须核实，如实披露，作者负责。**

### 合适与不合适的用法

| 合适（核实后使用） | 不合适 |
|---|---|
| 解释报错、调试代码、改写函数 | 让 AI 生成数据或“结果”，或修改数值使其显著 |
| 提示可能相关的方法和文献线索 | 直接引用 AI 给出的文献而不核对原文和 DOI |
| 润色语言、检查语法 | 让 AI 代写讨论和结论，自己不理解 |
| 解释一个陌生概念，再对照教材 | 把未公开的病人数据、受协议保护的数据上传到在线服务 |

::: {.callout-warn}
AI 编造参考文献是真实存在的问题：作者、标题、期刊看起来都合理，但文章并不存在，或 DOI 指向另一篇论文。报告中的每一条参考文献，都要通过 DOI 或数据库检索亲自打开核对。
:::

### AI 生成代码的可复算性

AI 生成的分析代码同样要满足本专题的所有要求：固定版本、记录种子、写测试。特别要检查它是否悄悄改变了默认参数（例如阈值、是否加权、是否去除自环）、是否在同一数据上既选择又检验、是否使用了已经弃用的函数接口。把 AI 的使用记录（工具、版本、日期、用于哪一步）写进运行记录，与其他软件版本一并存档。

### 如何披露

在报告的方法部分或致谢后加一段“AI 使用说明”，写清：工具名称和版本、使用的环节、你如何核实。示例：

> 本项目使用了某大语言模型助手（版本与使用日期）辅助调试 `02_build_network.py` 中的数据读取代码，并润色了引言部分的语言。所有代码均由作者逐行理解并在完整流程中重新运行；所有参考文献均由作者通过 DOI 核对原文。研究问题、分析设计、结果解释由作者完成并负责。

AI 工具不能列为作者。国际医学期刊编辑委员会（ICMJE）建议和多数期刊政策都要求在投稿时披露 AI 的使用，并由人类作者对全部内容负责。

## 数学推导与算法 {#derivations}

### Fisher z 变换与样本量公式

设样本相关 $r$ 来自二元正态总体，总体相关为 $\rho$。Fisher z 变换 $z = \operatorname{artanh}(r) = \tfrac12 \ln\frac{1+r}{1-r}$ 近似服从 $N\big(\operatorname{artanh}(\rho),\, 1/(n-3)\big)$。对原假设 $\rho = 0$ 的双侧检验，统计量 $Z = \sqrt{n-3}\, z$，拒绝域为 $|Z| > z_{1-\alpha/2}$。当真实值为 $\rho > 0$ 时，功效约为

$$
1-\beta \approx \Phi\!\left(\sqrt{n-3}\,\operatorname{artanh}(\rho) - z_{1-\alpha/2}\right),
$$

令其等于目标功效并解出 $n$，即得[统计功效与样本量](reproducible-research.power-sample-size.html)中的公式。对控制 $k$ 个变量的偏相关，有效样本量从 $n$ 变为 $n-k$。对 $m$ 条边做 Bonferroni 校正时，把 $\alpha$ 换成 $\alpha/m$；由于 $z_{1-\alpha/(2m)}$ 随 $m$ 只以约 $\sqrt{2\ln m}$ 的速度增长，节点数增加带来的样本量增长主要来自更弱的边和更多的控制变量。

### 经验 $p$ 值与蒙特卡洛误差

设检验统计量在原假设下的真实尾概率为 $p$，从零分布独立抽取 $B$ 个样本，其中不小于观测值的个数 $b \sim \mathrm{Binomial}(B, p)$。$b/B$ 的方差为 $p(1-p)/B$，故蒙特卡洛标准误为 $\sqrt{p(1-p)/B}$。若要求在 $p$ 接近显著性水平 $\alpha$ 时，标准误不超过 $\alpha$ 的 $c$ 倍，则需要 $B \ge (1-\alpha)/(c^2\alpha)$；例如 $\alpha = 0.05$、$c = 0.1$ 时 $B \ge 1900$。$(b+1)/(B+1)$ 这一形式相当于把观测数据本身视为零分布的一个样本，在原假设下 $P(\hat p \le u) \le u$，即检验是有效的（Phipson & Smyth 2010）。

### 循环分析为何产生偏倚

设有 $M$ 个特征，其组间差异的检验统计量 $T_1, \dots, T_M$ 在原假设下独立同分布于 $N(0,1)$。选出 $|T_j|$ 最大的若干个后，它们在同一数据上的值是次序统计量，期望约为 $\sqrt{2 \ln M}$ 量级而非 0，因此再用同一数据检验必然“显著”。若在独立数据上检验，被选特征的统计量仍服从 $N(0,1)$，偏倚消失。这就是分半或交叉验证能够纠正循环分析的原因。

### 设定曲线的联合推断

记 $S$ 个设定的效应估计为 $\hat\theta_1, \dots, \hat\theta_S$。选择一个汇总统计量 $g$（如中位数、显著设定数、同号设定数）。在原假设下生成数据的“零版本”（如打乱组标签，或从结局中减去估计效应），对每个零版本重新运行全部 $S$ 个设定并计算 $g$，得到 $g$ 的零分布，再用经验 $p$ 值判断观测的 $g$ 是否异常（Simonsohn 等 2020）。由于不同设定使用同一数据、彼此高度相关，不能把各设定的 $p$ 值当作独立检验直接计数。

## 研究前沿与开放问题 {#frontiers}

1. **网络研究的预注册模板**：心理网络已有报告标准（Burger 等 2023），但面向脑网络、分子网络、网络医学的预注册模板和报告清单仍不完善；怎样在不束缚探索的前提下规定“网络构建的分岔点”，是一个开放问题。
2. **大规模多元宇宙的计算与推断**：网络构建的选择组合动辄成百上千，主动学习近似（Dafflon 等 2022）和基于质量标准的流水线筛选（Luppi 等 2024）是两条路线；怎样在多元宇宙结果上做有效的联合推断仍在发展中。
3. **网络估计的样本量规划**：基于模拟的样本量方法（Constantin 等 2026）目前主要针对横断面高斯图模型，时间序列网络、多层网络、分子网络推断的功效分析工具尚不成熟。
4. **可复算性的自动核查**：自动在干净环境中重新执行共享代码的研究（Trisovic 等 2022）显示了自动化的潜力；容器化、持续集成与“可执行论文”正在被期刊采用，但长期可执行性（软件和数据库多年后的可用性）仍未解决。
5. **数据库版本漂移**：STRING、BioGRID、DisGeNET 等数据库持续更新，基于旧版本得到的疾病模块或药物重定位结论在新版本中是否成立，系统性的“版本敏感性”研究还很少。
6. **生成式 AI 与可复算性**：大语言模型的输出本身有随机性且模型版本会被替换，如何记录和复算 AI 参与的分析步骤，尚无公认规范。

## 生物医学应用 {#biomedical}

可复算和敏感性分析在生物医学网络研究中不是“额外加分”，而是结论能否被采信的前提。

在脑网络领域，阈值和图谱的选择会改变小世界性和枢纽排序（见[脑连接组：结构与功能连接](brain-connectome.html)），头动会制造虚假的短程连接，不同的网络构建流水线在可靠性和对头动的敏感程度上差异很大（Luppi 等 2024）；在症状网络领域，小样本下的中心性排序常常不稳定（见[症状网络与网络精神病学](symptom-networks.html)），跨样本的复现争论推动了报告标准的出台（Burger 等 2023）；在基因网络领域，推断出的单条边在真实数据上的准确度很有限（见[基因调控网络推断与共表达分析](gene-network-inference.html)）；在网络医学中，忽视度分布会系统性地高估枢纽靶点（见[疾病模块、网络邻近度与药物重定位](network-medicine.html)），参考网络的版本也会改变疾病模块的大小与显著性。这些都不是某个领域的特殊问题，而是同一条原则：**网络是构建出来的，构建方式本身就是结论的一部分。**

::: {.callout-bio}
**一个完整的稳健性方案（网络医学示例）**：研究问题为“某疾病基因在 PPI 网络中是否形成显著的连通模块”。预注册中写明：参考网络为 STRING（版本与下载日期），主分析置信度 0.7，敏感性分析取 0.4 与 0.9，并用另一个实验来源的相互作用组重复；零模型为度匹配随机基因集，$B = 10\,000$，种子事先确定；疾病基因来源及版本；若最大连通分支 $z$ 分数在所有设定中均 > 2 则视为稳健。所有代码、环境文件与基因列表存入带 DOI 的存储库，受许可限制的数据库只共享下载脚本。
:::

对于计划发表的研究，还应留意各领域的报告规范，例如影像研究的 COBIDAS（Nichols 等 2017）、心理网络的报告标准（Burger 等 2023）以及观察性研究的报告指南。本专题的[报告清单](reproducible-research.reporting-checklist.html)可以当作网络构建部分的补充。

## 适用范围与常见误用 {#limitations}

1. **误区**：固定了随机种子，结果就“可靠”了。→ **正解**：固定种子保证可复算；可靠性要求结论在多个种子下都成立，且随机网络数足够大。
2. **误区**：敏感性分析是找到最好看的参数。→ **正解**：先写明主分析和待检查的选择，再如实报告所有结果，包括不支持假设的。
3. **误区**：只要代码能运行，就算可复算。→ **正解**：还要记录数据版本、环境版本、手工步骤，并能从原始数据一键重跑出全部图表。
4. **误区**：代码和数据已经共享，研究就是可复现的。→ **正解**：共享材料常常缺少依赖、路径写死、版本不明；应在干净环境中实际重跑一次。
5. **误区**：预注册了就不能做计划外的分析。→ **正解**：可以做，但要标明为探索性，并报告与计划的偏离。
6. **误区**：多元宇宙中多数宇宙显著，结论就成立。→ **正解**：宇宙之间高度相关，不能当独立证据计数；有缺陷的选择不应纳入；需要联合推断。
7. **误区**：结果不显著是因为“功效不够”，用观测效应算一下事后功效即可说明。→ **正解**：事后功效只是 $p$ 值的变形；应报告效应量的置信区间，并在研究前做样本量规划。
8. **误区**：AI 只是润色了语言，不需要披露。→ **正解**：按多数期刊政策，任何实质使用都应说明用途和核实方式。

## 核心文献 {#references}

### Sandve 等 2013：Ten simple rules for reproducible computational research

- **背景**：计算研究的结果往往难以由他人甚至原作者复现。*PLoS Computational Biology* 9(10):e1003285，DOI [10.1371/journal.pcbi.1003285](https://doi.org/10.1371/journal.pcbi.1003285)。
- **核心内容**：十条可操作的规则，包括记录每个结果是如何产生的、避免手工修改数据、记录外部程序的版本、用版本控制、记录随机种子、保存图表背后的原始数值等。
- **阅读提示**：边读边对照自己的项目目录，逐条打勾；全文很短，约 30 分钟。
- **思考题**：十条规则中，哪一条在你的研究里最难做到？你打算怎样变通？

### Botvinik-Nezer 等 2020：Variability in the analysis of a single neuroimaging dataset by many teams

- **背景**：同一份数据，不同的合理分析流程会得到多大差异？*Nature* 582:84–88，DOI [10.1038/s41586-020-2314-9](https://doi.org/10.1038/s41586-020-2314-9)。
- **核心发现**：70 个团队独立检验 9 个预设假设，没有两个团队采用完全相同的流程；同一假设上各团队的结论一致性有限，分析流程的多个方面与结果差异有关；但各团队的中间统计图之间相关较高，跨团队的元分析得到了一致的激活区域。
- **阅读提示**：注意“中间结果相似、最终二元结论不同”这一现象——阈值化把连续证据变成了“是/否”，与[脑连接组](brain-connectome.html)中网络阈值的问题同源。
- **思考题**：如果你的分析交给 10 个团队独立完成，你认为哪一步最可能导致结论分歧？

### Steegen 等 2016：Increasing transparency through a multiverse analysis

- **背景**：数据处理阶段的“合理选择”会在不知不觉中影响结论。*Perspectives on Psychological Science* 11(5):702–712，DOI [10.1177/1745691616658637](https://doi.org/10.1177/1745691616658637)。
- **核心内容**：提出“数据多元宇宙”的概念，主张把所有合理处理选择下的结果一并报告，并用图示呈现结论对选择的依赖。
- **阅读提示**：把文中的“数据处理选择”替换为“网络构建选择”（图谱、边统计量、阈值），思考自己研究的多元宇宙有多大。
- **思考题**：你的研究中，哪些选择确实没有公认最优解、应放进多元宇宙？哪些选择应在事先就排除？

### Nosek 等 2018：The preregistration revolution

- **背景**：预测与事后解释在实践中常被混淆。*PNAS* 115(11):2600–2606，DOI [10.1073/pnas.1708274114](https://doi.org/10.1073/pnas.1708274114)。
- **核心内容**：阐述预注册如何区分验证性与探索性分析，并讨论数据已存在、需要偏离计划等不理想情形下的实用策略。
- **阅读提示**：重点读不理想情形的部分，它与使用公共数据库的网络研究最相关。
- **思考题**：如果你的数据已经下载并做过描述性统计，怎样设计一个仍然可信的预注册？

### Wilkinson 等 2016：The FAIR Guiding Principles for scientific data management and stewardship

- **背景**：数据共享需要让人和机器都能找到并重用数据。*Scientific Data* 3:160018，DOI [10.1038/sdata.2016.18](https://doi.org/10.1038/sdata.2016.18)。
- **核心内容**：提出可发现、可访问、可互操作、可重用四类原则及其细则，强调持久标识符、丰富元数据、标准词表与清晰许可。
- **阅读提示**：对照[数据与代码共享](reproducible-research.open-data-code.html)中的表格，检查你的网络数据是否满足每一条。
- **思考题**：受隐私限制无法公开的患者数据，怎样仍然满足 FAIR 中的“可发现”和“可访问”？

### Burger 等 2023：Reporting standards for psychological network analyses in cross-sectional data

- **背景**：心理网络分析缺少关于“报告什么”的规范，这为研究者自由度留下空间。*Psychological Methods* 28(4):806–824，DOI [10.1037/met0000471](https://doi.org/10.1037/met0000471)。
- **核心内容**：按方法与结果两部分，给出通用分析流程（样本、变量选择、预处理、估计方法及参数、准确性与稳定性、软件版本与种子）和特定分析流程（组间比较、中心性、边差异、聚类）的报告要求，并附两个用公开数据完成的示例。
- **阅读提示**：即使不做症状网络，“通用分析流程”部分也可直接迁移到脑网络和分子网络。
- **思考题**：把你最近读过的一篇网络论文按这份规范逐项核对，缺了哪些信息？

### Wilson 等 2017：Good enough practices in scientific computing

- **背景**：面向非专业程序员的研究者，什么是“足够好”的计算实践？*PLoS Computational Biology* 13(6):e1005510，DOI [10.1371/journal.pcbi.1005510](https://doi.org/10.1371/journal.pcbi.1005510)。
- **核心内容**：从数据管理、代码组织、协作、项目结构、版本控制、写作六个方面给出低门槛的建议，强调“先做到够用，再追求完美”。
- **阅读提示**：重点读数据管理和项目结构两节，可直接套用于自己的研究项目。
- **思考题**：作者建议“为每个项目准备一个 README”。请为你正在进行的一项分析写出 README 的前 10 行。

### Forbes 等 2017 与 Borsboom 等 2017：症状网络可重复性争论

- **背景**：Forbes 等，“Evidence that psychopathology symptom networks have limited replicability”，*Journal of Abnormal Psychology* 126(7):969–988，DOI [10.1037/abn0000276](https://doi.org/10.1037/abn0000276)；Borsboom 等，“False alarm? A comprehensive reanalysis …”，同刊 126(7):989–999，DOI [10.1037/abn0000306](https://doi.org/10.1037/abn0000306)。
- **核心内容**：前者认为条件独立网络的边和中心性在相似样本间复现差；后者重新分析后认为问题主要来自方法选择。
- **阅读提示**：把两篇对照阅读，列出双方在数据处理上的具体分歧，再看 Fried 等（2018）的多样本研究如何推进了这一问题。
- **思考题**：这场争论中，哪些分歧可以通过事先的报告规范和代码共享避免？

## 开放问题 {#questions}

1. 用[研究问题四要素表](reproducible-research.research-questions.html)改写一个你正在考虑的网络研究问题，并列出最可能改变结论的两个分析选择。怎样在报告中呈现这两项敏感性分析？
2. 为你的一项网络研究写一份一页的分析计划：哪些选择事先固定？哪些作为多元宇宙的维度？预计的宇宙数有多大，计算上是否可行？
3. 你的研究使用的公共数据库（如 STRING、HCP、TCGA）你已经接触过。怎样设计预注册或数据分割，使确认性分析仍然可信？
4. 如果网络有 30 个节点、你关心的边偏相关约为 0.15，按[样本量公式](reproducible-research.power-sample-size.html)估算所需样本量；与你实际能获得的样本相比，你会怎样调整研究问题？
5. 在你的研究领域，AI 工具最可能在哪一步帮你节省时间？最可能在哪一步引入不易察觉的错误？你会怎样设计核实流程？
